# قرارداد خوراک جلسه‌ی هوشینو — `hooshino-session/1.1`

این سند **الزام‌آور** است. هر فایل جلسه باید دقیقاً از آن پیروی کند.

هدف: مخزن دیگر فقط فهرست پرسش برای معلم نیست. **هرچه هوشینو برای ساختن سه بخش
یک جلسه لازم دارد اینجاست** — از متنی که دانش‌آموز روی صفحه می‌خواند تا معیاری که
پاسخش با آن داوری می‌شود.

---

## ۱) چهار تعامل مجاز

سکوی هوشینو فقط همین چهار کار را می‌تواند بکند. هیچ گام نباید چیز دیگری بخواهد.

| `interaction` | یعنی |
|---|---|
| `display` | فقط نمایش؛ دانش‌آموز می‌خواند و دکمه‌ی «ادامه» می‌زند |
| `text` | دانش‌آموز پاسخ را تایپ می‌کند |
| `image` | دانش‌آموز عکس بارگذاری می‌کند |
| `voice` | دانش‌آموز صدا ضبط و ارسال می‌کند |

`mode` هم یکی از `class` (کل کلاس با معلم)، `solo` (فردی روی دستگاه)،
`pair` (دونفره روی یک دستگاه؛ راننده/راهنما هر ۵ دقیقه جابه‌جا).

---

## ۲) ساختار فایل جلسه

```jsonc
{
  "schema": "hooshino-session/1.1",
  "grade": 5,
  "session": 1,
  "title": "قرارداد سال و پرسش بزرگ",
  "meta": {
    "goal": "…",                      // هدف جلسه
    "concepts": ["…"],                // مفاهیم کلیدی
    "mission": { "name": "…", "badge": "…" },
    "curriculumLink": { "area": "ریاضی — الگوسازی", "text": "…" },
    "tool": { "name": "…", "note": "…" },   // یا null اگر ابزار تازه‌ای باز نمی‌شود
    "materials": ["…"],
    "output": "…",                    // خروجی جلسه
    "teacherTip": "…",
    "minutes": 60
  },
  "preCheck": [ /* پیش‌سنجه؛ بخش ۲-الف — در جلسه‌ی بی‌شغل [] */ ],
  "parts": [ /* سه بخش، به همین ترتیب */ ],
  "pool": { "review": [], "example": [], "practice": [] },
  "device": { "work": "…", "challenge": {"1":"…","2":"…","3":"…"},
              "record": "…", "home": "…" }
}
```

### بخش‌ها (`parts`)

دقیقاً سه بخش، به ترتیب، با همین `kind` و همین دقیقه‌ها:

| `kind` | عنوان | دقیقه |
|---|---|---|
| `amoozesh` | آموزش | ۱۵ (در جلسات ۸ و ۱۶ و ۲۴ و ۳۲: ۵) |
| `taamol` | فعالیت تعاملی | ۳۵ (۴۰) |
| `arzyabi` | ارزیابی | ۱۰ (۱۵) |

جمع دقیقه‌ی گام‌های هر بخش باید **دقیقاً** برابر دقیقه‌ی آن بخش باشد.

در جلسه‌های ۲ به بعد، گام نخستِ `amoozesh` باید **۵ دقیقه** و از نوع مرور باشد.
هوشینو پس از صفحه‌ی مرور، کارت‌های `pool.review` را با پاسخشان نشان می‌دهد.

### بخش آموزش فقط نمایشی است (از ۱.۱)

همه‌ی گام‌های `amoozesh` باید `interaction: "display"` و `answer.mode: "none"` باشند.
آموزش از هیچ دانش‌آموزی ورودی نمی‌گیرد تا:

* در **آموزش مجازی**، محتوای صفحه بدون توضیح معلم کافی باشد؛
* در **جلسه‌ی دونفره**، لازم نباشد هر نفر جدا چیزی وارد کند.

به همین دلیل آموزش به‌جای ۲ تا ۳ گام، ۶ تا ۷ صفحه دارد: تعریف مفهوم، **مثال حل‌شده**
(`kind: "example"`)، کارت چهارپرسشی ابزار و معرفی شغل. هر صفحه `screen.image` دارد.
پرسیدن و پاسخ‌گرفتن به `taamol` و `arzyabi` سپرده شده است.

### ۲-الف) پیش‌سنجه (`preCheck`)

گویه‌ی K1 پنجره‌ی مشاغل («می‌دانم در این شغل چه کاری انجام می‌شود») باید **پیش از هر
توضیحی** ثبت شود. چون آموزش دیگر ورودی نمی‌گیرد، این گویه به `preCheck` منتقل شد:

* آرایه‌ای از گام‌ها با `kind: "precheck"` و `minutes: 0` (بیرون از ۶۰ دقیقه)؛
* هنگام ورود **هر** دانش‌آموز و پیش از بخش آموزش، روی دستگاه خودش پرسیده می‌شود؛
* در جلسه‌هایی که شغل ندارند، `preCheck: []`.

## ۳) گام (`step`) — واحد اصلی

```jsonc
{
  "id": "G5-S01-A1",           // A=آموزش، T=تعامل، E=ارزیابی + شماره
  "seq": 1,
  "kind": "review|teach|example|activity|practice|reflect|mission|wrap|precheck",
  "minutes": 7,
  "mode": "class",
  "interaction": "display",
  "screen": {
    "title": "…",              // تیتر روی صفحه، حداکثر ۶ کلمه
    "body": "…",               // متنی که دانش‌آموز می‌خواند — همین متن نمایش داده می‌شود
    "bullets": ["…"],          // اختیاری، حداکثر ۴ قلم کوتاه
    "image": "G5-S01-E01"      // اختیاری، شناسه‌ی تصویر در assets/
  },
  "ask": "…",                  // پرسشی که از دانش‌آموز می‌شود؛ برای display برابر null
  "answer": { … },             // بخش ۴
  "hints": ["…", "…", "…"],    // دقیقاً سه سطح؛ برای display برابر []
  "feedback": { "correct": "…", "partial": "…", "incorrect": "…" },
  "commonErrors": [ { "error": "…", "reply": "…" } ],
  "teacherNote": "…"           // فقط در PDF معلم؛ هرگز به دانش‌آموز نشان داده نمی‌شود
}
```

**قاعده‌ی سفت:** `screen.body` همان چیزی است که واقعاً روی صفحه می‌آید. آن را به
زبان دانش‌آموز بنویس («تو…»، «بیا…»)، نه به زبان معلم («معلم نشان می‌دهد…»).
متن معلم‌محور به `teacherNote` می‌رود.

## ۴) حالت پاسخ (`answer.mode`) — مهم‌ترین بخش

بعضی پرسش‌ها پاسخ از پیش تعیین‌شده دارند و بعضی نه. هوشینو باید بداند با کدام
روبه‌روست، وگرنه یا پاسخ خلاقانه‌ی درست را رد می‌کند یا پاسخ غلط را می‌پذیرد.

### `"mode": "fixed"` — پاسخ معین

```jsonc
"answer": {
  "mode": "fixed",
  "value": "ب",
  "accept": ["ب", "هدفون روی گوش", "هدفون"],
  "aiInstruction": "فقط تطبیق بده. اگر پاسخ در accept بود درست، وگرنه نادرست. املای کمی متفاوت را بپذیر."
}
```
برای چندگزینه‌ای، بله/خیر، محاسبه، و هر چیزی که یک پاسخ درست دارد.
`accept` باید همه‌ی صورت‌های پذیرفتنی را داشته باشد (حرف گزینه، متن گزینه، شکل کوتاه).

### `"mode": "ai"` — پاسخ باز، داوری با هوش مصنوعی

```jsonc
"answer": {
  "mode": "ai",
  "criteria": [
    "به تکرارشدن یا قاعده‌داشتن اشاره کند",
    "دست‌کم یک نمونه بیاورد"
  ],
  "sample": "…",              // یک پاسخ نمونه‌ی خوب، برای کالیبره‌کردن داور
  "aiInstruction": "اگر هر دو معیار آمد «درست»؛ اگر فقط یکی آمد «نیمه» و همان معیار جامانده را بپرس؛ اگر هیچ‌کدام نیامد «نادرست» و راهنمایی سطح ۱ را بده. به املا و نگارش امتیاز نده."
}
```
برای پاسخ باز، استدلالی، طراحی، داوری. `criteria` باید **قابل بررسی** باشد، نه کلی.
«خوب توضیح بدهد» معیار نیست؛ «دست‌کم دو تفاوت نام ببرد» معیار است.

### `"mode": "none"` — بدون پاسخ

برای گام‌های `display`. `hints` خالی و `feedback` فقط `correct` دارد (پیام ادامه).

## ۵) راهنمایی و بازخورد

`hints` **دقیقاً سه قلم**، به این ترتیب:

1. **تلنگر** — فقط توجه را به جای درست می‌برد. هیچ محتوایی لو نمی‌رود.
2. **مسیر** — می‌گوید چطور فکر کند، نه اینکه پاسخ چیست.
3. **تقریباً پاسخ** — آن‌قدر می‌گوید که دانش‌آموز خودش خط آخر را بردارد.

`feedback` سه حالت دارد و هر سه باید نوشته شود:
- `correct` — تأیید + یک جمله که *چرا* درست بود.
- `partial` — چه بخشی درست بود و دقیقاً چه چیزی کم است.
- `incorrect` — بدون سرزنش، با دعوت به تلاش دوباره.

`commonErrors` خطاهای رایجِ قابل پیش‌بینی را با پاسخ آماده می‌آورد (صفر تا سه قلم).

## ۶) مخزن (`pool`)

همان سه دسته‌ی قبلی، ولی هر قلم حالا ساختار کامل گام را دارد (`screen`، `answer`،
`hints`، `feedback`).

| دسته | تعداد | نکته |
|---|---|---|
| `review` | ۱۰ | جلسه‌ی ۱ ندارد (آرایه‌ی خالی). **کارت نمایشی**: پرسش + پاسخ روی کارت |
| `example` | ۱۰ | **مثال حل‌شده‌ی نمایشی** — متن درس، نه روایت معلم |
| `practice` | ۱۰ پرسش | `level` ۱ تا ۳ با توزیع ۳/۴/۳ (بر پایه‌ی پرسش، نه قلم) |

اقلام `review` و `example` جزو بخش آموزش‌اند، پس مثل آن فقط نمایشی‌اند
(`interaction: "display"`). پاسخ مرور و راه‌حل مثال در خود `screen.body` آمده است.

هر قلم `poolKind` و شناسه‌ی قدیمی خود را نگه می‌دارد (`G5-S01-E03`) تا با
تصویرهای `assets/` و CSV فعلی بخواند.

`practice` علاوه بر گام، `type` دارد: چندگزینه‌ای، کوتاه‌پاسخ، بله یا خیر،
بازنویسی، دسته‌بندی، عملی، استدلالی، طراحی، داوری، محاسبه، تطبیق، پیش‌بینی.

### پرسش‌های چندجای‌خالی (از ۱.۱)

هیچ قلم ارزیابی نباید در یک کادر چند پاسخ جدا بخواهد (سه قرار، شش گویه، سه جمله برای
دسته‌بندی، آغاز و پایان، …). چنین پرسشی به چند قلم جدا شکسته می‌شود:

```jsonc
{ "id": "G5-S01-P02-1", "group": "G5-S01-P02", "groupPart": 1, "groupSize": 3, … }
```

* `id` = شناسه‌ی پرسش اصلی + `-` + شماره‌ی پاره؛
* همه‌ی پاره‌ها `level` و (در صورت وجود) تصویر پرسش اصلی را دارند؛
* هوشینو پاره‌ها را پشت‌سرهم و به ترتیب `groupPart` می‌پرسد و هر کدام را جدا داوری می‌کند؛
* شمارش «۱۰ تمرین» و توزیع سطح، بر پایه‌ی `group` (یا `id` برای پرسش تک‌پاره) است.

در `arzyabi` هم کارت شغل به **هفت گام جدا** شکسته شده است: شش گویه (I1، K1، S1، V1،
E1، A1؛ هر کدام یک دقیقه، با `itemCode`) و یک پرسش باز Q.

**مسیر مشترک:** `parts` برای همه‌ی دانش‌آموزان یکسان اجرا می‌شود؛ فقط `practice`
بر پایه‌ی عملکرد همان دانش‌آموز سطح‌بندی می‌شود.

## ۷) سیاست هوش مصنوعی (`aiPolicy`)

در سر فایل هر پایه می‌آید و بر همه‌ی جلسه‌ها حاکم است:

* زبان فارسی ساده و کودکانه؛ جمله‌ی کوتاه؛ بدون اصطلاح فنی توضیح‌نداده.
* **هرگز پیش از سه راهنمایی، پاسخ را نگو.**
* هرگز دانش‌آموزان را با هم مقایسه نکن و هیچ رتبه‌ای اعلام نکن.
* به املا و دست‌خط امتیاز نده مگر خود گام همان را بخواهد.
* اگر دانش‌آموز چیزی خارج از درس پرسید، کوتاه پاسخ بده و به گام برگردان.
* اگر پاسخ نامربوط یا خالی بود، بدون قضاوت دوباره بپرس.
* در گام `pair`، خطاب را دونفره کن («شما دو نفر…»).
* در بخش آموزش هیچ پرسشی نپرس؛ صفحه‌ها را به‌ترتیب نشان بده.
* پیش‌سنجه را جدا از هر دانش‌آموز بپرس.
* بازخورد همیشه با کاری که دانش‌آموز *کرد* شروع شود، نه با درست/غلط بودنش.

## ۸) قواعد نوشتن

* همه‌ی ارقام داخل متن فارسی: ۰۱۲۳۴۵۶۷۸۹. عدد در فیلدهای عددی (`minutes`,
  `seq`, `level`) عدد لاتین معمولی است.
* نیم‌فاصله رعایت شود: می‌کند، بزرگ‌تر، شکل‌ها.
* `screen.body` حداکثر ۵۵ کلمه. اگر بیشتر شد، به دو گام بشکن.
* هیچ ارجاعی به پایه‌های قبل («پارسال یاد گرفتید») — هر پایه مستقل است.
* مواد فقط از فهرست مجاز: کاغذ و مداد و مدادرنگی، تبلت شخصی با هوشینو،
  هدفون و میکروفون، نمایشگر کلاسی. (چاپگر فقط در جلسات ۳۱ و ۳۲.)
* نام نرم‌افزار همیشه «هوشینو».
